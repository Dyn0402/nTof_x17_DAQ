    Size of each ~70 s n_TOF stream1 raw file on EOS (xrdfs ls -l — sizes only, no file contents read). A SiPM wall dropping out removes its hits and roughly halves the file, so each file is graded per proton pulse (a file holds one event per pulse, so this is what removes the beam) against the typical full level over a trailing window: good at or above 90% of it, questionable below that, and bad below 75%. Files that saw no beam are not graded at all. Absolute size is not comparable across run configs, hence the moving reference. Times are EOS mtimes (file close), converted from UTC to local. Logged to —.

    Detector Gain vs Nominal —
    detectorchflash nominalvs nominal ZS blocksnotes
    no waveform sample yet

    Gamma-flash amplitude per detector from the first event of a sampled file, against a frozen healthy reference. The flash is in every proton pulse, so it is an absolute gain reference — a detector that keeps its baseline and noise but loses the flash has lost gain, not statistics. Graded bad below 50% of nominal, questionable below 85%. Baseline / noise deviations appear in notes: those point at the digitiser or DC path instead. Nominal is never auto-updated, and re-freezing it is refused while the walls are down.
