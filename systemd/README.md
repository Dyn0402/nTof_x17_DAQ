# systemd units for the mx17 DAQ host

Snapshot of the boot-time units that were installed on `mx17` during the
2026 July/August beam campaign, kept here so the machine can be brought back
up the same way later. These files are **copies** — the live ones are under
`/etc/systemd/system/`. Editing anything here has no effect until it is
installed (see below).

| File | Installed as | What it does |
| --- | --- | --- |
| `daq-startup.service` | `/etc/systemd/system/daq-startup.service` | Runs `start_servers.sh` at boot as user `mx17` — brings up the tmux sessions, Flask app (port 5001), and all the watchers. |
| `daq-startup.service.d/10-network-online.conf` | same path under `/etc/systemd/system/` | Delays the start until `network-online.target`. |
| `daq-startup.service.d/50-MemoryLow.conf`, `50-MemorySwapMax.conf` | originally `/etc/systemd/system.control/daq-startup.service.d/` | Memory protection (`MemoryLow=4G`, `MemorySwapMax=0`). These were generated by `systemctl set-property`, not hand-written. |
| `daq-net-tuning.service` + `daq-net-tuning-boot.sh` | `/etc/systemd/system/`, `/usr/local/sbin/` | NIC ring buffers + `performance` CPU governor (ZS/IPD study, 2026-07-18). Sysctls live separately in `/etc/sysctl.d/99-custom.conf`. |
| `eos-x17.service` | `/etc/systemd/system/eos-x17.service` | XRootD FUSE mount of `/eos/experiment/ntof/data/x17`. Needs a valid Kerberos ticket at `/tmp/krb5cc_1000` (the hourly `kinit` cron keeps it fresh). |

## Current state

`daq-startup.service` was **disabled** at the end of the campaign
(2026-08-12) so the DAQ no longer comes up automatically on reboot.
`daq-net-tuning.service` and `eos-x17.service` were left enabled — they are
harmless without the DAQ running.

## Disabling / re-enabling

```bash
# stop autostart at boot (leaves anything already running alone)
sudo systemctl disable daq-startup.service

# bring it back
sudo systemctl enable daq-startup.service
```

`disable` only affects the *next* boot. To stop a currently running DAQ, use
the **Soft Shutdown** button in the Flask monitor panel — it stops the
watchers in the right order (`mode_watcher` first). Do not `systemctl stop`
the unit and do not SIGKILL anything: the N1081B boards wedge on dirty
disconnects (see `n1081b/CLAUDE.md`).

Note that the unit has `KillMode=none`, so `systemctl stop` would leave the
child processes running anyway.

## Reinstalling from scratch on a fresh host

```bash
cd /home/mx17/PycharmProjects/nTof_x17_DAQ/systemd
sudo cp daq-startup.service daq-net-tuning.service eos-x17.service /etc/systemd/system/
sudo mkdir -p /etc/systemd/system/daq-startup.service.d
sudo cp daq-startup.service.d/*.conf /etc/systemd/system/daq-startup.service.d/
sudo install -m 755 daq-net-tuning-boot.sh /usr/local/sbin/
sudo systemctl daemon-reload
sudo systemctl enable daq-startup.service daq-net-tuning.service eos-x17.service
```

The memory limits can equivalently be re-applied without the drop-in files:

```bash
sudo systemctl set-property daq-startup.service MemoryLow=4G MemorySwapMax=0
```

Paths inside the units are hard-coded to
`/home/mx17/PycharmProjects/nTof_x17_DAQ` and user `mx17` — fix those first
if the repo lands anywhere else.
